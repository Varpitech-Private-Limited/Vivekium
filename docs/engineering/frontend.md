# Frontend rules

**Status:** current. **Reviewed:** 2026-10-14. Loaded on demand by `.claude/rules/frontend.md`.
Design authority: [../../DESIGN.md](../../DESIGN.md) and [../../PRODUCT.md](../../PRODUCT.md) (the Impeccable tooling resolves both at the repository root).

## Stack and layout

- Next.js 16 App Router, TypeScript strict, Server Components by default; `"use client"` only for interactivity. shadcn/ui primitives in `components/ui/` are not hand-edited; wrap or compose.
- Routes are grouped by audience: `(public)`, `(auth)`, `(org)` Customer Portal, `(candidate)` Candidate Portal, `(super-admin)` Provider Portal, `(bd)` Business Development Portal. Never interchange the portal names.
- The browser decides nothing about assessment, ranking or time: no client sort, arithmetic, number or timer logic. It renders server words and the server's own sentences verbatim.
- `proxy.ts` must name every generated route that has no file extension (`/icon`, `/apple-icon`, robots, sitemap, opengraph image) or a signed-out request gets a 307.

## Permissions in the UI

- Ask `can(...)` (`lib/permissions.ts`, `lib/use-permissions.ts`), never the role. Import `CAP.x`, not a string literal.
- A resource-scoped answer from the server (`can_edit` on a payload) beats the capability list. A 403 refreshes the capability snapshot.
- A read-only sentence is rendered by `components/permission-notice.tsx` and nowhere else; it shows only when the user can view and genuinely cannot edit (`lib/read-only-messaging.test.ts`).

## Copy

- No number ever appears beside an assessment: grades are words. A countdown shown as `m:ss` is a deadline, not an assessment number.
- No em dash anywhere, including seeded and generated content. Never name a storage vendor in user copy. Page titles do not repeat the site name (`%s | Vivekium`).
- Use only the recruiter vocabulary of decision P-05. `lib/user-facing-copy.test.ts` reads structure and asserts a floor on what it swept.
- A promise printed on a control is a claim about the code. A failed read is never rendered as an empty answer; `apiErrorMessage` reads the server's `detail`.
- A deleted feature leaves no screen, route, nav entry or string. A server sentence is shown verbatim, never paraphrased.

## Visual system

- Navy is structure, teal is evidence. Text is never grey (enforced at the token). Teal text on white is `teal-700`; `teal-600` is fill, rule and icon only. No gradient between two hues. `brand-*` aliases `navy-*`; new work uses `navy-*` and `teal-*`. Dark mode is a black field (`#000000` page, near-black cards, `#FFFFFF` text, white primary buttons with black labels), not a navy canvas.
- The brand mark is a drawn V, geometry rather than a raster (`components/brand/logo.tsx`; the favicon and Apple icon are generated by `app/icon.tsx` and `app/apple-icon.tsx`). A designed mark is an open owner decision (Q-20).
- Typography follows DESIGN.md section 3. The theme toggle lives only in Settings and Profile.
- `frontend/scripts/impeccable-gate.mjs` fails CI on any finding not listed with a reason in `.impeccable-exceptions.md`.

## Assessment surfaces

- Paste, copy, cut and drop are refused in every answer field, each reported with its kind. The editor for code answers is Monaco, self-hosted (pinned exact, copied to `public/monaco/vs`); its scripts pass `proxy.ts` like a page. Ctrl or Cmd plus Enter never submits. **The coding surface is under decision S-20 (no sandbox); do not extend the Run or hidden-test UI.**
- A 409 puts a typed answer back into the field. The draft goes to the server keyed by turn. The face freezes the countdown during a pause and re-reads the server at zero.
- Candidate pages use one application form (`components/apply-form.tsx`).
- The frontend dev container does not see file changes over the Windows bind mount: restart the `frontend` service after editing.
